Step 1

Build the app in Claude as an Artifact

An Artifact is a web page Claude builds and hosts for you inside claude.ai. It's the fastest way to design and test the app before it goes anywhere public.

Why start with an Artifact

  • Instant preview. You see the app working as soon as Claude writes it, and every change appears straight away.
  • Built-in storage. Artifacts can save data in claude.ai, so the app is genuinely usable while you shape it.
  • Private by default. Only you can open it until you share it.
  • Easy to move later. Once you're happy, Claude Code turns the same page into a standalone website (Step 4).

Describe the app

Start in Claude Code (or claude.ai) and say what you want, who uses it and what it must do. Be concrete about the screens and the numbers. You can refine everything afterwards, so don't try to be perfect.

Prompt: first version
Build me a web app as an Artifact: a <what it is, e.g. stock tracker / booking list / habit tracker> for <who uses it>.

It needs:
- <the main things people enter, e.g. items and quantities, bookings, daily entries>
- <the totals or summaries to show at the top>
- Double-click (or tap) any value to edit it, with a "Save changes?" confirmation before anything is saved
- Data saved so it is still there next time I open it

Keep it clean and simple, light theme, and make it work well on a phone.

Refine it in small steps

Ask for one change at a time, check it, then ask for the next. Short, specific requests work best:

  • "Rename Notes to Comments and add an Add another button under it."
  • "Make the page lock itself after 30 minutes of no activity."
  • "Before deleting anything, ask if I'm sure and show what will be removed."
  • "The previous layout was better, put it back." Claude can undo just as easily.
Tip: always test on a phoneOpen the Artifact link on your phone as well as your computer. Phones behave differently: for example, they won't pop up the keyboard for a field the page focuses by itself, so a PIN screen works best with an on-page number keypad.

What works inside claude.ai and what doesn't

Artifacts run inside a protected frame on claude.ai. A few browser features behave differently there:

FeatureInside an ArtifactOn your own website
Saving dataclaude.ai's built-in storage (only for signed-in people the Artifact is shared with)Your own server function (Step 4)
Print dialog (window.print())Blocked: nothing happensWorks
Downloading a file (PDF, backup)Through claude.ai's download promptNormal browser download
Knowing who is using itclaude.ai can tell the page who is signed inYou add your own (for example a name picker)

None of this stops you. Just tell Claude what you saw ("I clicked Print and nothing happened") and it will switch to an approach that works, such as generating the PDF as a download.

Sharing the Artifact

From the Artifact's Share menu you can invite people by email. Viewers can look; to edit they need a higher role (Contributor or above). Anyone opening it must be signed in to Claude for the saved data to load. If you need it open to people without Claude accounts, that's the point to move to your own site.
