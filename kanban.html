App idea

Drag-and-drop boards: a Kanban for projects and tasks

A board of columns with cards you drag from one column to the next is one of the most useful things you can build with Claude. Each card is a task or a job, each column is a stage, and moving a card is how you update its status. Try the one below, then copy the prompts to build your own.

Try it

Drag a card to another column or up and down to reorder it. On a phone, drag by the ⠿ handle. With a keyboard, tab to a card and use the arrow keys. Changes are kept in this browser only.

Example: a small home-office project

Keyboard: ← → move a card between columns, ↑ ↓ reorder it, Delete removes it.

What you could use it for

Any work that moves through stages fits a board. Change the column names and the card details to suit:

1. Build the board

Prompt: a Kanban board app
Build a Kanban-style task board as an Artifact for <what it's for, e.g. tracking jobs for my business>.
- Columns: <e.g. To do, In progress, Waiting, Done>. Let me add, rename, reorder and remove columns.
- Each column shows its card count and has an "Add card" box at the bottom.
- A card shows its title and <e.g. due date, who it's assigned to, a coloured label>.
  Clicking a card opens it to edit the title, notes and those details, or delete it.
- Overdue cards get a red due date; cards due today an amber one.
- A search box and filters (by label, by person) that hide cards that don't match.
- Works well on phones: columns stack one under another below 640px wide.
- Light and dark theme that follows the device.

2. Drag and drop that also works on phones

This is the part most likely to go wrong. The browser's built-in drag and drop (draggable="true") works with a mouse but does nothing on most phones and tablets. Ask for it to be built with pointer events instead, which handle mouse, touch and pen the same way.

Prompt: drag and drop for mouse, touch and keyboard
Make cards draggable between columns and up and down within a column:
- Use Pointer Events (pointerdown / pointermove / pointerup with setPointerCapture),
  not the HTML5 draggable API, so it works with touch as well as a mouse.
- With a mouse, drag the whole card. On touch, drag by a small handle (⠿) with
  touch-action: none, so swiping elsewhere still scrolls the page.
- Start the drag only after the pointer moves 5px, so a click still opens the card.
- While dragging: the card follows the pointer, a gap shows where it will land,
  the target column is highlighted, and the page auto-scrolls near the top or bottom edge.
- Escape cancels the drag and puts the card back.
- Keyboard: focus a card and use ← → to move it between columns and ↑ ↓ to reorder,
  with a screen-reader announcement like "Moved 'Order parts' to Done, position 2 of 4".
- Save the new column and position of every card straight after each drop,
  so the order is the same after a reload.
Check it on a real phoneDesktop browsers' phone preview doesn't always behave like a real touch screen. Open the Artifact (or the live site) on your phone and drag a few cards before moving on.

3. Saving the board

Quick path (just you):

Prompt: save on this device, with backups
Save the board in the browser's localStorage after every change (wrapped in try/catch,
so the app still works if storage is blocked). Add "Export board" (downloads a JSON file
named "<Board name> YYYY-MM-DD.json") and "Import board" (asks before replacing
the current board). Show a small "Saved" note after each change.

Full path (shared): add the must-have features first, then:

Prompt: a shared board for several people
This board is shared by <number> people on different devices.
- Store each card's column and position on the server, inside the encrypted data.
- Log every move in the transaction log in plain English, e.g.
  "<name> moved 'Order parts' from In progress to Done".
- If someone else changed the board since I loaded it, refuse my save, reload the
  latest board and tell me what changed, instead of overwriting their work.
- Check for changes from others every 30 seconds while the page is open
  and refresh the board if there are any (without interrupting a drag in progress).

Ideas to add later

  • Work-in-progress limits. "Highlight the In progress column when it has more than <3> cards." It's the simplest way to stop starting more than you finish. The demo above does this.
  • Swimlanes. Rows across the board per person, client or project, so one board can show several streams of work.
  • Checklists on cards. Sub-tasks with tick boxes, and a "3 / 5" progress bar on the card.
  • Archive the Done column. A "Clear Done" button that moves finished cards to a searchable archive, using the archive feature.
  • Board templates. "New board from template" with preset columns for each kind of project you run.
  • Reports. A PDF or CSV of what was finished this week or month, from the move log (see reports).
  • Calendar view. The same cards laid out by due date, as a second tab.

Common snags

  • Dragging works on the computer but not the phone. It was built with the HTML5 draggable API. Paste the drag prompt above and ask Claude to switch to pointer events.
  • Trying to drag on a phone scrolls the page instead. The handle needs touch-action: none.
  • Clicking a card starts a drag, or dragging opens the card. Ask for the 5px movement threshold before a drag starts.
  • The order is wrong after a reload. Only the column was saved, not the position. Ask Claude to store a position number for every card and save after each drop.
  • Two people moved cards at once and one move was lost. Add the conflict handling from the shared-board prompt.
