Step 3

Give Claude Code a GitHub token, safely

A personal access token is a password-like key that lets Claude Code create a repository and upload your app's code for you. A fine-grained token can be limited to exactly what's needed and revoked at any time.

Create the token

  1. Sign in to GitHub and open Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Token name: something you'll recognise, for example claude-code-deploy.
  3. Expiration: 90 days is a good balance. You'll make a new one when it runs out.
  4. Repository access: pick one of these (see the note below):
    • All repositories: simplest. Claude can publish new apps without you changing the token each time.
    • Only select repositories: safer, but you must add each new repo to the token before Claude can upload to it.
  5. Repository permissions, set these and leave everything else as No access:
    PermissionLevelWhy
    AdministrationRead and writeCreate new repositories
    ContentsRead and writeUpload and update the code
    MetadataRead-onlyAlways required (set automatically)
    PagesRead and writeOnly if Claude should switch on GitHub Pages for a repo (this also needs Administration: Read and write)
  6. Click Generate token and copy it. GitHub shows it only once. (When you edit a token later, the button is Update at the bottom of the page; changes aren't saved until you click it.)
The most common snagWith Only select repositories, Claude can create a new repo but then gets 403 Resource not accessible by personal access token when uploading to it. The fix: edit the token, add the new repo under Repository access, make sure Contents is Read and write, and save. Nothing needs to be regenerated.

Hand the token to Claude Code without pasting it in chat

Anything typed into a chat is kept in the conversation history and logs. Put the token in a file instead and tell Claude where it is.

  1. Create a text file containing only the token on one line, for example C:\secrets\github-token.txt (Windows) or ~/secrets/github-token.txt (Mac/Linux). Keep it outside any folder that gets uploaded.
  2. Tell Claude Code where it is:
Prompt: hand over the token
My GitHub fine-grained token is in <path to token file>.
Don't print it or put it in any file you publish.
First run a read-only check: which account it belongs to, its type, and which repos it can see.

Claude will reply with something like "fine-grained token for account yourname, can see 2 repos". That confirms the token works before anything is created.

Use a separate token per purposeIf you already have a token for another job (for example releasing a different tool), don't reuse it. A dedicated token keeps each job's access separate and lets you revoke one without breaking the other.

Keeping the token safe

  • Never put it in the app's code, a README, a screenshot or a chat message.
  • If it ever leaks, delete it on the same GitHub page straight away; anything using it stops working immediately.
  • When it expires, generate a new one with the same settings and overwrite the file. Claude picks up the new one automatically.
