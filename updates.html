Step 7

Making changes later: the automatic push process

Once everything is connected, improving the app is a conversation. You ask, Claude makes the change and publishes it, and the live site updates by itself, with your data untouched.

What happens when you ask for a change

BackupClaude saves the live data first
→
EditClaude changes the local source

PushOne commit to GitHub main

DeployNetlify builds and switches over
  1. You ask in Claude Code, for example "add a savings goal at the top".
  2. Claude backs up the live data with the admin script, so there's a fresh copy before anything changes.
  3. Claude edits the source in the local project folder (and the Artifact too, if you keep both in step).
  4. Claude pushes with the publish script: one commit to the main branch on GitHub.
  5. GitHub tells Netlify a new commit has arrived. This was set up automatically when you imported the repo.
  6. Netlify builds the new version. Only if the build succeeds does it switch the live site over, all at once. If it fails, the old version simply stays live.
  7. Open pages pick it up on their next reload. The data, stored separately, is exactly as it was.
It's pushes, not "Releases"Netlify reacts to every push to the production branch (main). You don't need to create GitHub Releases or tags.

A good change request

Prompt: make a change to the live app
For <app name>: <describe the change, e.g. "add a savings goal box at the top showing progress">.
Follow the usual process: back up the live data first, make the change, publish it to GitHub
with a clear commit message, then check the live site has the new version.
Tell me if the change needs anything from me (like a new Netlify setting).

Where to watch it happen

  • Netlify → Deploys lists every deploy with its commit message and status, and has a log for each build.
  • Site configuration → Build & deploy → Continuous deployment shows which repo and branch the site follows.
  • GitHub → your repo → Commits shows every change Claude has published.

Rolling back a bad change

Two different kinds of "undo":

ProblemFix
The new code has a bugIn Netlify → Deploys, open an earlier deploy and click Publish deploy for an instant rollback. Then ask Claude to fix the code properly.
The data got damagedAsk Claude to restore from the backup it took before the change, or from a saved version (see Step 6).

Keeping the Artifact and the site in step

You can keep developing in the Artifact if you prefer its instant preview, then ask Claude to carry the change over to the site. Or retire the Artifact and work on the site only. Either way, say which one is the "real" one so data isn't edited in two places.
