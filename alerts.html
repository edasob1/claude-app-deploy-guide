Add-on

Send alerts to your phone with ntfy

ntfy ("notify") is a free, open-source push notification service. Your app sends a short message to a web address, and the ntfy app on your phone pops it up straight away, like a text. There's no account to create, no API key and nothing to pay for normal personal use.

How it works

Your appSomething happens: a new entry, a bill due, low stock
→
ntfy.sh/<topic>The app posts a message to your private topic
→
Your phoneThe ntfy app shows it as a notification

A topic is just a name you make up, like a channel. Anything posted to that topic goes to every phone subscribed to it, so you can also subscribe a partner's or a colleague's phone to the same one.

Treat the topic name like a passwordOn the free public server there's no login: anyone who knows or guesses the topic name can read your alerts and send you fake ones. Use a long, random name such as myapp-alerts-k7q2x9m4w8, never something like alerts or your name, and keep personal details out of the messages (see Keep it private).

1. Set up your phone

  1. Install ntfy from the Google Play Store or the Apple App Store (it's also on F-Droid). On a computer you can use the web app at ntfy.sh/app.
  2. Open it and allow notifications when asked.
  3. Tap + (Subscribe to topic), type your random topic name, leave the server as ntfy.sh, and tap Subscribe.
  4. On Android, if alerts arrive late, open the phone's battery settings and set ntfy to Unrestricted so the system doesn't put it to sleep.

2. Send yourself a test

Before involving the app, check the phone side works. Paste one of these into a terminal on your computer, with your own topic name. Your phone should buzz within a second or two.

Windows PowerShell
Invoke-RestMethod -Method Post -Uri "https://ntfy.sh/<your-topic>" -Body "Hello from my computer" -Headers @{ Title = "Test alert"; Tags = "tada" }
Mac / Linux terminal
curl -H "Title: Test alert" -H "Tags: tada" -d "Hello from my computer" https://ntfy.sh/<your-topic>

Or just ask Claude Code: "Send a test ntfy alert to the topic <your-topic>."

4. Add alerts to a Netlify site

Give this to Claude Code in the folder of your site. It sends the alert from the server, so the topic name never appears in the page.

Prompt: ntfy alerts from a Netlify function
Add phone push alerts to my site using ntfy (https://ntfy.sh):
- Send them from the server (a Netlify function), never from the browser.
- Read the topic from the environment variable NTFY_TOPIC. Also support optional
  NTFY_SERVER (default https://ntfy.sh) and NTFY_TOKEN (sent as "Authorization: Bearer ...")
  in case I later use a protected topic or my own server. If NTFY_TOPIC isn't set, skip alerts silently.
- POST the message text as the body, with these headers:
  Title: a short summary, Priority: "high" (or "urgent" for <what counts as urgent>),
  Tags: an emoji name such as "bell", Click: a link that opens the right page of my site.
- Send an alert when: <e.g. a new booking or form is submitted / a record is marked urgent>.
- Messages must not contain personal details (names, phone numbers, amounts). Say what
  happened and link to the site, e.g. "New booking received. Tap to open."
- A failed alert must never stop the save itself: log the error and carry on.
- Tell me which environment variables to add in Netlify, then send a test alert.
  1. In Netlify, open your site, then Site configuration → Environment variables → Add a variable. Key NTFY_TOPIC, value your random topic name.
  2. Redeploy (Netlify only picks up new variables on the next deploy): Deploys → Trigger deploy, or ask Claude to publish.
  3. Do whatever triggers the alert on the live site and check your phone.

Alerts on a schedule

Netlify can also run a function on a timer, which is handy for reminders and daily summaries even when nobody has opened the app.

Prompt: a scheduled reminder
Add a Netlify scheduled function that runs <e.g. every day at 7am New Zealand time>
and sends an ntfy alert (using the same NTFY_TOPIC settings) when <e.g. a bill is due in
the next 3 days / stock of anything is below its minimum / no backup has been made for 7 days>.
Send nothing when there's nothing to report. Remember the schedule is in UTC, so convert my time.
Encrypted appsIf your data is encrypted with a PIN (Step 2), the server can't read it, so a scheduled function can't see what's due. Either alert from the page when someone saves ("New entry added"), or store just the dates the reminder needs, unencrypted and without any other detail.

5. Alerts on a quick-path site

A GitHub Pages site has no server, so the page sends the alert itself while it's open. ntfy accepts calls straight from a browser, so this works, but the topic name sits in the page where anyone can read it.

Prompt: ntfy alerts from the page
Add ntfy phone alerts to this page. Send a POST with fetch() to https://ntfy.sh/<topic>
with a Title header and the message as the body, when <e.g. a timer finishes / a task is overdue>.
Put the topic in a Settings box (saved in localStorage, wrapped in try/catch) rather than in the
code, with a "Send test alert" button next to it. Never include personal details in the message.
If sending fails, show a small warning instead of an error pop-up.

Keep alerts rare. If the phone buzzes for everything, you'll start ignoring it or mute it.

Keep it private

  • Say that something happened, not the details. "New job logged, priority high" is fine. Customer names, addresses, phone numbers and amounts don't belong in an alert: the message passes through a public server and sits on the phone's lock screen.
  • Use a long random topic and keep it out of public code. On Netlify it lives in NTFY_TOPIC; on the quick path, in the page's settings rather than the repository.
  • If the topic leaks, pick a new random name, change it in Netlify (or the page's settings) and resubscribe on your phone. Old messages are only kept on the server for a short time.
  • Want it locked down? A paid ntfy.sh account can reserve a topic so only you can use it, with an access token for your app (NTFY_TOKEN). Or run your own ntfy server (NTFY_SERVER). The prompt above already supports both, so it's only a settings change.

Common snags

  • The test from the computer works but the site sends nothing. NTFY_TOPIC was added after the last deploy. Trigger a new deploy in Netlify.
  • Nothing arrives at all. Check the topic is spelled exactly the same in the app and on the phone; topics are case-sensitive. Then try the test command above.
  • Alerts arrive minutes late, or only when the phone is unlocked. Android battery saving is pausing ntfy. Set its battery use to Unrestricted.
  • "Too many requests" (HTTP 429). Something is sending in a loop. Ask Claude to send at most one alert per event, and to group a burst into one summary.
  • Nothing is sent from the Artifact. The Artifact sandbox blocks calls to outside sites. Test alerts on the live site instead.
  • Someone else's messages turned up. Your topic name was too easy to guess. Switch to a long random one.
