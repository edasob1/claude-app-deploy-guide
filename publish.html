Step 4

Claude turns the Artifact into a website and publishes it

An Artifact relies on features that only exist inside claude.ai, mainly its storage. Before it can live on its own address, Claude Code converts it into a standalone site with a small server function for the data, then uploads it to a new GitHub repository.

What changes in the conversion

Inside claude.aiOn the website
claude.ai storage (db)A Netlify Function that stores the encrypted document in Netlify Blobs
claude.ai download promptA normal browser download
claude.ai knows who is signed inA name picker on the unlock screen
Live updates from claude.aiThe page checks for changes every 20 seconds and when the tab comes back into view

The encryption stays exactly the same, so the data format is identical and a backup moves straight across.

The prompt

Run this in Claude Code (in the terminal), in the folder where you keep your projects.

Prompt: convert and publish
Take my Artifact <artifact link> and build a standalone version to host on Netlify, deployed from GitHub.

Project
- Put the source in <local folder, e.g. C:\Projects\my-app\site>: index.html, netlify.toml,
  package.json and netlify/functions/.
- Replace the claude.ai storage with a Netlify Function at /api/vault using Netlify Blobs.
  The browser keeps encrypting; the server stores ciphertext only.
- Saves must prove the PIN: derive a write token from the PIN-derived key, store only its SHA-256
  on the server, and refuse saves without it. Reject a save based on an out-of-date revision (409)
  instead of overwriting someone else's change.
- Optional SETUP_CODE environment variable: if set, creating the first budget needs it.
- Keep the last 30 saved versions on the server automatically.
- Admin backup/restore endpoint at /api/backup, switched off unless an ADMIN_KEY environment
  variable is set. Generate a 64-character admin key into <path outside the project> and write me a
  PowerShell script with Backup, List and Restore actions that uses it.
- Keep the stored document format identical to the Artifact version, and add Export Backup /
  Import a backup file (see the export/import prompt).
- Add noindex and basic security headers.

GitHub
- My token is in <path to token file>. Create a private repo <owner>/<repo-name> and upload the
  site folder as one commit through the GitHub API (I don't have git installed).
- Save that upload as a reusable script: Publish.ps1 -Message "what changed".
- Also add an Export Backup button to the Artifact so I can move my data across.

Don't put any token, key or PIN in the repo or in chat. Tell me exactly what I need to do in Netlify afterwards.

What Claude does

  1. Builds the site in the local folder and the server functions next to it.
  2. Creates the repository on your GitHub account (private) through the API.
  3. Uploads everything as one commit: it uploads each file, builds a file tree from them, creates a commit and moves the main branch to it. This is what git push does, without needing Git installed.
  4. Lists the repo to confirm every file arrived.
  5. Saves the upload as a script (for example Publish.ps1) so every future change goes up with one command.

The project layout you'll end up with

Files in the repository
index.html                    the whole app (React and Tailwind from CDNs, no build step)
netlify.toml                  tells Netlify where things are; adds security headers
package.json                  one dependency: @netlify/blobs
netlify/functions/vault.mjs   /api/vault  - load and save the encrypted data
netlify/functions/backup.mjs  /api/backup - admin backup / restore (needs ADMIN_KEY)
netlify/lib/versions.mjs      keeps the last 30 saved versions
README.md                     what it is and which environment variables it needs
Private or public repository?Private is the right default for an app with personal data. Netlify can deploy private repos once you give it access. (GitHub Pages, by contrast, needs a public repo on the free plan, which is why this guide itself is public.)

Help Claude remember the setup

Claude Code has a memory between sessions. Ask it to record the project so you never have to explain it again:

Prompt: remember the project
Save a memory for this project: where the source lives, the repo name, the live URL, where the
token and admin key files are, and the rule "back up the live data before every change, then
publish with the script". Don't store the token, key or any PIN in the memory itself.
