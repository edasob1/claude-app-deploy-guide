Quick path

Simple sites with no database: publish straight to GitHub Pages

If your app doesn't need to save shared data, you can skip Netlify completely. GitHub hosts the pages for free, and Claude Code can create the repo, upload the files and switch the site on for you. This guide itself was published this way.

Is the quick path right for your app?

Good fit for GitHub PagesNeeds the full path (Netlify)
Guides, documentation, portfolios, landing pagesData that several people or devices share
Calculators, converters, quizzes, checklistsA login that protects stored data
Tools that keep data only on the device (browser storage), with Export/Import to move itServer-side backups, version history, admin restore
Games and demosAnything with secret keys (they can't be hidden on GitHub Pages)
Everything on GitHub Pages is publicOn the free plan, the repository must be public, so anyone can read every file. Never include personal data, keys, passwords or private notes in the code.

1. Build the site

Build it as an Artifact first (see Step 1), or ask Claude Code to write the files straight into a folder. Plain HTML, CSS and JavaScript work best: no build step, nothing to install.

Prompt: a simple site
Build a simple static website in <local folder>: <what it is>.
- Plain HTML, CSS and a little JavaScript, no build step, no server
- One page per topic, with shared navigation, Previous / Next links, and a menu that works on phones
- Light and dark theme that follows the device, with a toggle
- Relative links only (it will be served from https://<user>.github.io/<repo>/)
- Nothing personal or secret in any file, because the repo will be public
Saving data without a serverA static site can still remember things on the person's own device with browser storage. Ask for an Export / Import button too, so people can back up or move their data. It just won't be shared between devices or people.

2. Token permissions for GitHub Pages

Use a fine-grained token as in Step 3, with these repository permissions:

PermissionLevelWhy
ContentsRead and writeUpload the files
AdministrationRead and writeCreate the repo, and needed to switch Pages on
PagesRead and writeSwitch GitHub Pages on
MetadataRead-onlyAlways required
Both Pages and Administration are neededSwitching Pages on through the API needs both permissions. With only one, GitHub answers 403 Resource not accessible by personal access token. After editing a token, remember to click Update at the bottom of the page, or the change isn't saved.

3. Claude publishes it

Prompt: publish to GitHub Pages
Publish the site in <local folder> to GitHub Pages.
My token is in <path to token file> (don't print it or put it in any file).
1. Check nothing personal or secret is in the files, because the repo will be public.
2. Create a public repo <owner>/<repo-name> and upload the folder as one commit through the GitHub API.
3. Add a short README with the live link.
4. Switch on GitHub Pages from the main branch, root folder.
5. Save the upload as a reusable script (Publish.ps1 -Message "...") for later changes.
6. Check the live site loads and tell me the address.
If GitHub refuses a step, tell me exactly which permission is missing.

Behind the scenes Claude uploads the files, creates a commit and moves the main branch to it, then calls GitHub's Pages API to publish from main.

4. Switch Pages on by hand (if you prefer)

If you'd rather not give the token Administration and Pages rights, this takes 30 seconds:

  1. Open your repo on GitHub and go to Settings → Pages.
  2. Under Build and deployment, set Source to Deploy from a branch.
  3. Choose Branch: main and / (root), then click Save.
  4. After a minute or two, the address appears at the top of that page: https://<user>.github.io/<repo>/.

Making changes later

Same as the full path, minus the data: ask Claude for the change, it edits the files and runs the publish script, and GitHub Pages rebuilds automatically, usually within a minute or two. Progress shows under the repo's Actions tab ("pages build and deployment").

Prompt: update the simple site
For my site <repo-name>: <describe the change>. Publish it with the script and check the live page shows it.

Common snags

  • The site shows a 404 at first. The first build takes a minute or two. Check the repo's Actions tab, then reload.
  • Styles or links broken on the live site but fine locally. A link starts with /, so it points at github.io/ instead of github.io/<repo>/. Ask Claude to make every link relative.
  • Old version still showing. Browsers cache pages. Hard-reload with Ctrl+F5 (Windows) or Cmd+Shift+R (Mac).
  • Want a private repo? GitHub Pages from private repos needs a paid GitHub plan. Netlify can host a private repo's site for free instead.
